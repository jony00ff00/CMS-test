# Node CMS

Node-based CMS: Document Source → Selector → Snippet → Output.
Sources (.html, .docx, .json) become one internal Document (a hast tree). Selectors pick parts of it,
Snippet nodes wrap or add to those parts, and Output previews or exports the result.

## Rules
- `src/engine` must stay pure TS: no React, no DOM APIs, no `.tsx`. All logic is tested with Vitest.
  `tests/engine/smoke.test.ts` enforces this.
- Nodes never change their inputs; `evaluate` returns new values.
- Each node type lives in `src/engine/nodes/<name>.ts` and is registered in `src/engine/nodes/index.ts`.
- The preview always renders in `<iframe sandbox="allow-scripts">` via `srcdoc`.
- Fixtures are generated by `npm run fixtures` into `tests/fixtures/` (git-ignored), never committed by hand.
  `npm test` and `npm run e2e` regenerate them first.
- Document sources: .html, .docx, .json. All become the same hast Document.
- JSON blocks always have `data-json-path`. Never remove it in a snippet transform
  (wrap outside it or inside it, never replace it).
- JSON write-back must only change the mapped fields; everything else in the file stays the same.
- `@playwright/test` is pinned to 1.63.0 to match the Chromium preinstalled in the cloud environment.
  Do not run `playwright install` or upgrade it without checking that.

## Engine API (so far)
- `types.ts`: `CmsDocument` (hast `tree` of body content, `meta`, `assets`), `Anchor`, `Selection`, `Snippet`.
- `document.ts`: `parseHtml` (drops scripts, event handlers, `javascript:` URLs and comments; collects `<style>`;
  collapses whitespace like a browser), `serialize` (`fullDocument`, `inlineAssets`), `buildTextIndex`
  (visible text, blocks separated by `\n`, each segment mapped to its text node and path), `locate`, `nodeAtPath`.
- `docx.ts`: `importDocx` via mammoth, loaded on demand to keep the main bundle small. Images become assets
  referenced as `asset:<id>`. Custom `styleMap` rules take precedence over the defaults.
- `json.ts`: `parseJson` (own error scanner gives line, column and a plain reason in every browser),
  `discoverPaths` (every string field, with a suggested format), `mapJsonToDocument` / `importJson` (async).
  Field mode: each matched string becomes a block with `data-json-path`, read as `text`, `html` or `markdown`;
  `meta.json` keeps a copy of the data, the mapping and each block's exact path segments for write-back.
  Template mode: Handlebars renders the whole file (`{{markdown x}}` and `{{json x}}` helpers), no write-back.
  No mapping means every string field as text. Paths that match nothing or non-strings give warnings, not errors.
- `source.ts`: `importSource({ name, data }, { json, docx })` picks the importer by file extension.
- Large libraries (mammoth, Handlebars, the Markdown parser) are loaded with `import()` only when needed.
  Keep it that way; the main bundle should stay near 430 kB.

## Commands
- `npm run dev`: dev server
- `npm test`: unit tests (must pass before every commit)
- `npm run e2e`: Playwright tests (builds, serves on :4173, headless Chromium)
- `npm run build`: type check + build
- `npm run fixtures`: regenerate the test .html, .docx and .json files

## Definition of done for any task
Tests added, `npm test && npm run build` green, and a screenshot of the UI if it changed
(e2e tests write screenshots to `test-results/`).

## Roadmap
M0 scaffold · M1 document engine · M1b JSON import · M2 selectors and anchors · M3 snippet application ·
M4 graph engine · M5 canvas UI · M6 preview and visual selection · M7 snippet library · M8 persistence and export.

## Deployment
`.github/workflows/pages.yml` runs unit tests, builds with `VITE_BASE=/<repo-name>/`, and deploys `dist/`
to GitHub Pages on every push to `main`. Local builds keep base `/`.
