# Node CMS

Node-based CMS: Document Source → Selector → Snippet → Output (plus Extractor, Object, Connector, Combinator).
Sources (.html, .docx, .pptx, .json) become one internal Document (a hast tree). Selectors pick parts of it,
Snippet nodes wrap or add to those parts, and Output previews or exports the result.

## Rules
- `src/engine` must stay pure TS: no React, no DOM APIs, no `.tsx`. All logic is tested with Vitest.
  `tests/engine/smoke.test.ts` enforces this.
- Nodes never change their inputs; `evaluate` returns new values.
- Each node type lives in `src/engine/nodes/<name>.ts` and is registered in `src/engine/nodes/index.ts`.
- The preview always renders in `<iframe sandbox="allow-scripts">` via `srcdoc`.
- Fixtures are generated by `npm run fixtures` into `tests/fixtures/` (git-ignored), never committed by hand.
  `npm test` and `npm run e2e` regenerate them first.
- Document sources: .html, .docx, .pptx, .json. All become the same hast Document.
- JSON blocks always have `data-json-path`. Never remove it in a snippet transform
  (wrap outside it or inside it, never replace it).
- JSON write-back must only change the mapped fields; everything else in the file stays the same.
- `@playwright/test` is pinned to 1.63.0 to match the Chromium preinstalled in the cloud environment.
  Do not run `playwright install` or upgrade it without checking that.

## Engine API (so far)
- `types.ts`: `CmsDocument` (hast `tree` of body content, `meta`, `assets`), `Anchor`, `Selection`, `Snippet`.
- `document.ts`: `parseHtml` (drops scripts, event handlers, `javascript:` URLs and comments; collects `<style>`;
  collapses whitespace like a browser), `serialize` (`fullDocument`, `inlineAssets`), `buildTextIndex`
  (visible text, blocks separated by `\n`, each segment mapped to its text node and path), `locate`, `nodeAtPath`.
- `docx.ts`: `importDocx` via mammoth, loaded on demand to keep the main bundle small. Images become assets
  referenced as `asset:<id>`. Custom `styleMap` rules take precedence over the defaults.
- `pptx.ts`: `importPptx` (JSZip + @xmldom/xmldom, loaded with `import()`; mammoth uses the same two, pinned to
  its versions). One `<section class="slide" data-slide="N" data-layout="…">` per slide in the deck's slide list
  order (not file names). Placeholders without a type get it from the layout (by `idx`); title / ctrTitle → `<h2>` /
  `<h1>`, subTitle → `<p class="subtitle">`, body paragraphs are bullets unless `buNone`, other shapes are
  paragraphs unless `buChar` / `buAutoNum`; levels (`lvl`) → nested `<ul>` / `<ol>`. Footers, dates and slide numbers
  are skipped. Order: title, other placeholders, other shapes, each by y then x; groups are read through.
  Runs keep bold / italic / underline / strike / sup / sub and http(s) / mailto links. Notes → `<aside
  class="speaker-notes">`. Options `includeNotes` (true), `includeHidden` (false), `slides` (`parseSlideRange`,
  "1-5, 8"). `meta.pptx` lists every slide (number, title, hidden, included, layout). xmldom returns "" for
  missing attributes: read them with `attr()` (and `relId()` for r:id / r:embed / r:dm). Tables → `<table>` (`firstRow`
  → `<thead>` / `<th>`, `gridSpan` / `rowSpan` → colspan / rowspan, `hMerge` / `vMerge` cells skipped; one plain
  paragraph goes straight into the cell). Pictures → `<figure class="slide-picture"><img src="asset:pptx-<hash>"
  alt width></figure>` (alt from `descr`, link from the picture's `hlinkClick`, one asset per distinct image; EMF /
  WMF / TIFF, external and missing files warn). Charts → `<figure class="slide-chart">` with a table of the cached
  data (categories × series) and the title as caption, with a warning. SmartArt → `<div class="slide-smartart">`
  nested list following the data model's `parOf` connections. Videos, sounds and OLE objects warn (P6).
  Picture / table placeholders rank with the other placeholders in reading order. `slideStyles` (default true) adds
  `SLIDE_CSS` to `meta.styles` (cards, "Slide N" / "Notes" labels from `::before`, so the text index is unchanged);
  `formatSlideRange` writes [1,2,3,5] as "1-3, 5". .ppt / password-protected files
  (OLE header) get a plain error.
- `slide-deck.ts`: `toSlideDeck(doc)` for Output format `slides`: keeps `section.slide`s (warns about top-level content
  outside them), or splits other documents at top-level h1 / h2 (also a block that starts with one, e.g. a callout
  around it); adds `DECK_VIEWER` as a snippet asset (CSS + JS). The viewer only styles once its script ran
  (`html.cms-deck`), so the page reads fine without JS; slides are 960 × 540 scaled to fit (`--cms-deck-scale`);
  keys ←/→/Space/PgUp/PgDn/Home/End, N notes, `#3` opens slide 3 (replaceState in try: sandboxed preview).
  Its bar is `data-cms-preview` (not measured). The JS gets `document` / `window` as `d` / `w` parameters
  (`})(document, window)`), so the engine purity check holds.
- `json.ts`: `parseJson` (own error scanner gives line, column and a plain reason in every browser),
  `discoverPaths` (every string field, with a suggested format), `mapJsonToDocument` / `importJson` (async).
  Field mode: each matched string becomes a block with `data-json-path`, read as `text`, `html` or `markdown`;
  `meta.json` keeps a copy of the data, the mapping and each block's exact path segments for write-back.
  Template mode: Handlebars renders the whole file (`{{markdown x}}` and `{{json x}}` helpers), no write-back.
  No mapping means every string field as text. Paths that match nothing or non-strings give warnings, not errors.
- `source.ts`: `importSource({ name, data }, { json, docx })` picks the importer by file extension.
- `selectors.ts`: `runSelector(doc, config)` → `Selection` (never throws; problems become `warnings`).
  Modes: `css` (hast-util-select), `regex` (text ranges, or `scope: 'block'` for the enclosing block),
  `heading` (heading plus everything up to the next heading of the same or higher level), `jsonField`
  (JSONPath over `meta.json.data`, selects the mapped blocks), `manual` (stored anchors), `all` ("Everything":
  `scope: 'document'` one run of all top-level nodes without edge whitespace, or `'blocks'` each top-level element),
  `slide` (`slides` range by deck number, `title` contains, `part`: slide / title / content (one run of the slide's
  children without title and notes) / notes; warns for slides not in the document, slides lacking the part, and
  documents without slides). `slidesOf(ix)` / `slideAt(ix, offset)` in `doc-index.ts` find `section.slide`s.
- Matches are `NodeMatch` (sibling run: `parent` path, `start`..`end` child indexes) or `TextMatch`
  (text index offsets). `doc-index.ts` holds the shared lookups (`indexDocument`, `rangeOf`, `textOf`, sections).
- `anchors.ts`: `createAnchor` stores a text quote with context plus structural, CSS, heading and JSON-path
  strategies. `resolveAnchor` returns `exact` / `moved` / `fuzzy` / `failed` with a confidence and a reason.
  Identical text always wins over similar text. Default `minConfidence` 0.75. Index once and pass the
  `DocIndex` when resolving many anchors. On slides, anchors store `slide: { number, title }`: candidates on the
  slide with that title (or that number, untitled) win and are needed for the quick accept; one found only on
  another slide is `moved` at ×0.85 confidence (`OTHER_SLIDE_FACTOR`).
- Snippet node: `custom` ({ className, wrap: none | div | span }) makes the snippet (`customSnippet`: attributes
  `class="…"`, or a wrapper with the class) instead of `snippet`; `css` / `js` on any Snippet node are added as a
  snippet asset `node-<hash>` (once per distinct code). Store: `makeCustomSnippet`; `useLibrarySnippet` /
  `detachSnippet` clear `custom`; `saveNodeSnippetToLibrary` saves a custom one with its CSS / JS.
- `snippets.ts`: `applySnippet(selection, snippet, { params, snapToBlock })` (async: Handlebars loads on demand)
  → `{ document, warnings, applied }`. Modes: wrap, prepend, append (`inside` for first/last child), replace,
  attributes (merges class and style; selected text gets a <span>). Template variables: `{{content}}` (the
  original nodes), `{{text}}`, `{{html}}`, `{{index}}`, `{{number}}`, `{{count}}`, `{{part}}`, `{{parts}}`,
  `{{params.x}}`, `{{jsonPath}}`, `{{match.x}}` (from the `matchData(index)` option). Template output is cleaned like any HTML. CSS/JS go to
  `meta.snippetAssets` once per `id@version`; `serialize(..., { fullDocument: true })` writes them out.
- `ranges.ts`: `Workspace`, a working copy of the tree. Matches become node references before anything
  changes, and splits are recorded, so overlapping matches stay valid in any order. Text ranges split text
  nodes and partly covered inline elements, never block elements or JSON field blocks: a range across
  blocks gives one piece per block (or one run of whole blocks with `snapToBlock`).
- `text-match.ts`: bounded Levenshtein, Dice, and `fuzzyFind` (closest substring, Sellers' algorithm).
- `hast-util-select`'s `:scope` gives wrong results on our root; generated CSS paths avoid it.
- Never read the end of a string built with `+=` in a loop (it copies the string each time); collect parts and join.
- Large libraries (mammoth, Handlebars, the Markdown parser) are loaded with `import()` only when needed.
  Keep it that way. Libraries needed at start are split into `react`, `flow` and `html` chunks
  (`codeSplitting.groups` in `vite.config.ts`); list only eagerly loaded libraries there, or a group pulls lazy
  ones into the start-up download. The app's own chunk is about 135 kB; the build warns above 800 kB per chunk.
- `graph.ts`: `Graph` (`nodes`, `edges` with `sourcePort` / `targetPort`), `NodeDefinition` (typed `inputs` /
  `outputs`, `defaultConfig`, `evaluate`, optional `dependencies` for things outside the config such as a
  file's hash). `edgeError` / `connect` reject unknown ports, mismatched port types (`document`, `selection`,
  `html`, `result`; an `any` input takes all), a second connection into one input (unless the port has `multiple: true`, which then gets an array in
  edge order; reorder with `moveEdge`), the same connection twice, self-loops and loops. `topologicalSort`, `downstreamOf`,
  `validateGraph` (for loaded files). `GraphEvaluator.evaluate(graph, { files })` → per-node `NodeResult`
  (`ok` / `waiting` / `error` / `blocked`, outputs, warnings, info, `cached`) and `ran`. A node's cache key
  hashes its type, config, dependencies and the keys of its inputs, so a change re-runs only that node and
  the nodes after it. Only `ok` results are cached (LRU, default 200). Files live in a store
  (`storeFile(name, data)` adds a content hash); Document Source nodes refer to them by `fileId`.
- `library.ts`: `SnippetLibrary` (id → versions, oldest first). `addVersion` numbers versions; saved versions
  never change. `refStatus` (outdated / missing), `carryParams` (keep values that still fit), `validateSnippet`,
  `snippetIdFor`. The seed snippets (callout, details, highlight, tooltip, code-block) are content, so they live
  in `src/snippets/seed.ts`, outside the engine (the code block's JS mentions `document`).
- `json-export.ts`: `exportJson(doc, { assets })` writes a field-mode JSON document back into its file. A field's
  value is the HTML inside its block plus any wrappers around that block alone (e.g. `<details>`); text fields
  that are still plain paragraphs go back as text; untouched fields keep their original value exactly (compared
  with a fresh import). Content outside fields and wrappers around several fields are reported as warnings.
- `insert.ts`: content to insert (`code` as a block or as HTML, `image` / `video` from an uploaded file in the
  store, `imageUrl` / `videoUrl` by address; YouTube and Vimeo become embeds; only http(s) addresses) and where:
  `{ mode: 'point', point: { anchor, place } }` (picked in the preview) or `{ mode: 'selector', selector, place }`;
  places are before / after / start / end. Widths (`cssWidth`): any CSS length with a unit, a plain number means
  px, empty means 100%, anything else warns and uses 100%; applied as `style` (on the figure when captioned,
  the media then fills it; on the image, not the link, for linked images). Placement reuses `applySnippet` (prepend / append with a placeholder
  that is swapped for the built nodes), so overlap and JSON-field rules hold. Block content (video, code, figure)
  never goes inside a paragraph: it moves next to it, with a warning. Uploaded media become assets
  (`asset:insert-<hash>`). `insertionPointAt(doc, offset, 'cursor' | 'before' | 'after')` turns a click into a
  point ("cursor" anchors up to 24 characters before the cursor, from a word boundary). `markInsertionPoint` adds
  preview-only markers (`data-cms-preview`, which the bridge ignores when it measures text).
- `nodes/`: `documentSource` (`fileId`, `json` mapping, `docx` style map), `selector` (a `SelectorConfig`),
  `snippet` (`snippet` = the node's own copy, `ref` = `{ id, version }` when it came from the library,
  `params`, `snapToBlock`; default is the library's Callout v1), `output` (input `document` takes several connections. `combine: 'merge'` (default, `mergesInputs`) applies every
  input's changes to one document (`mergePorts(config)` on a node definition lists the ports to merge, in order; only
  `document`-typed sources merge): `planMerges` in `merge.ts` finds the latest document all inputs share and runs
  hidden copies (`<output>~<i>~<id>`) of each later input's nodes on the previous input's result, so selectors and
  points re-resolve on the changed text; the copies' results are dropped, `info.combined` is set. Inputs with no
  shared document, and `combine: 'append'`, go one after another (`combineDocuments` in `combine.ts`); JSON export
  refuses only in that case; `format` html | json | slides (always a complete page; info `slides`), `fullDocument`, `inlineAssets`, `jsonAssets`; always makes `html` for the
  preview, plus `json` when exporting JSON). Manual selectors report `info.needsAttention`;
  `selector` (`SelectorNodeConfig` = a `SelectorConfig` + `place`): outputs `selection` and `point` (port type
  `point`, a `PointValue` { kind: 'point', document, where: `InsertWhere` }): mode `point` (picked in the preview;
  waits until picked) gives `{ mode: 'point', point }`, every other mode `{ mode: 'selector', selector, place }`
  (place default after);
  `object` (was Insert: `content` only; input `point` (required) + optional `selection` input (`PortDef.optional`:
  the node runs without it) used by content `{ kind: 'selection' }`; `insertContent` at the point's `where`; depends
  on its media file's hash; reports `needsAttention` when its point is gone). `copySelection` in `insert.ts` copies
  what a selection matched, in document order, via a wrap snippet with a `cms-extract` marker; the copy drops
  `data-json-path` and brings its images and the source's snippet assets; connecting a selection to an Object
  switches it to that kind in `connect`. `parseProject` turns old `insert` nodes into a Selector `<id>-point`
  (their `where`) feeding an Object with the same id;
  `extractor` (a `SelectorConfig`, any mode but point; outputs a document of only what it picked:
  `documentFromSelection` in `convert.ts`; its outputs also carry `selection`, not a port, for the preview and the
  saved selections' status);
  `combinator` (inputs `a` / `b`, both `any` and optional; `combine` merge (default; `mergePorts` ['a', 'b']: two
  changed versions of one document become one; two selections / points in the same document become one selection)
  or append (A then B, `combineDocuments`); outputs like the Connector's);
  `connector` (one input `input` of port type `any`, which `edgeError` lets every output type into; outputs
  `document`, `selection`, `html` and `result`, all filled from whatever came in by `convertValue` in `convert.ts`
  (`valueKind`: a string is HTML, `kind: 'selection'` a selection, `kind: 'point'` a point (its document, and as a
  selection the places it stands for), anything else a document / result). Documents pass as the same object
  (snippet assets, JSON meta kept); a selection becomes a new document of its content (`copySelection`, default)
  or its whole document (`selectionToDocument`); a document becomes a selection of everything or each block
  (`documentToSelection`); HTML is read with `parseHtml` and passed on unchanged; other HTML out is `serialize`d
  (`fullPage`, default true). `parseProject` renames old edges into a connector's `result` input to `input`).

## UI (so far)
- Nodes can be named (`GraphNode.name`, `renameNode`, one undo step while typing; never re-evaluates). Show nodes
  with `nodeLabel(node)` (`src/ui/node-label.ts`): the name, or the id. Rename in the inspector's Name field or by
  double-clicking a node's title on the canvas (`NodeTitle` in `CmsNode.tsx`; the input is `nodrag` and stops key
  events so Backspace does not delete the node).
- Inspector header: Duplicate (`duplicateNode`: settings, name + " copy", incoming connections, placed below,
  one undo step; also Ctrl/Cmd+D outside fields) and Delete (`removeElements`). Connections use the `deletable`
  edge type (`DeletableEdge.tsx`): a delete button at the middle while selected. In e2e, click a connection by
  position between its handles (a straight one has no height).
- Node colours: CSS `--node-*` / `--port-*`, and `NODE_COLORS` (`src/ui/node-colors.ts`) for the minimap; keep them
  the same. Connector is grey; the `point` port and its dotted connections are cyan.
- "Save project file…" opens `SaveDialog` (`src/ui/canvas/SaveDialog.tsx`, a `<dialog>`): a file name
  (`projectFileName`, `.node-cms.json`, remembered in localStorage `node-cms:project-name`), then the browser's own
  save dialog (`showSaveFilePicker`, to pick the folder; cancelling it keeps our dialog open), or a download where
  that API is missing. e2e stubs `showSaveFilePicker` (`save-dialog.spec.ts`) or sets it to undefined.
- Panels can be minimised (`src/ui/panels.tsx`: `useMinimisedPanels`, remembered in localStorage
  `node-cms:minimised-panels`; `MinimiseButton` in each panel's header). Layout: four columns, palette · canvas ·
  inspector · preview (the preview is the rightmost sidebar). A minimised palette or inspector is replaced by a
  36 px `PanelRail` (the inspector's shows the selected node); grid widths come from `--palette-width` /
  `--inspector-width` / `--preview-width`. A minimised preview stays mounted (it may be showing in its own window)
  as a 36 px strip (`RailButton`, noting "in its own window"); while it is in its own window the column is 240 px.
  The canvas is a size container: below 860 px wide the project toolbar moves under the example buttons.
- `src/store/editor-store.ts`: zustand store (`createEditorStore` for tests, `editorStore` / `useEditor` in the
  app). Holds `graph`, `files`, `selectedId`, `results`, `notice`. Changes to the graph or files re-evaluate
  after 150 ms; position-only changes do not. Stale evaluations are dropped. `whenIdle()` for tests.
- `src/ui/canvas`: React Flow canvas. Nodes live in local state (React Flow stores measured sizes on them) and
  are synced from the store; positions go back on drag end. `isValidConnection` uses `edgeError`;
  `onConnectEnd` shows why a drop on a wrong handle was refused. `CmsNode` renders any node type from its
  definition (ports as handles named after the port).
- `src/ui/inspector`: one editor per node type (`EDITORS` in `Inspector.tsx`), plus `ResultPanel`.
- `src/ui/preview`: what it shows follows the selected node: a Selector shows its *input* with its matches
  highlighted (`highlightSelection` in `engine/preview.ts`, attributes mode, `data-cms-match` /
  `data-cms-status`); a Document Source or Snippet shows its output document; an Output (or nothing selected)
  shows the first Output's page. Always `<iframe sandbox="allow-scripts">` via `srcdoc`, so the editor cannot
  read the page: `bridge.ts` is injected and talks over `postMessage` (`source: 'cms-preview'`). It rebuilds
  the engine's text index from the DOM using `BLOCK_TAGS`, so selections come back as engine text offsets
  (an e2e test checks the two agree for HTML, .docx, JSON and .pptx). Elements marked `data-cms-preview` are ignored.
- The preview sidebar can be resized (`PreviewResizer` on its left edge: drag with pointer capture so the iframe
  does not swallow the pointer, ←/→ (left: wider), Home / End, double-click resets; 260 px to window width − 720,
  default 440; remembered in localStorage `node-cms:preview-width`; `App` sets `--preview-width` on the grid) and opened in its own
  window (`preview-window.ts`: an about:blank window of the editor's origin, the editor's styles copied in,
  the preview rendered there with a React portal; still a sandboxed iframe inside). Messages from the
  preview then arrive at that window, so `Preview` listens on the iframe's own window, and the bridge accepts
  messages from `parent.opener` as well as `parent`. Closing or reloading the window brings the preview back.
- Document Source with a .pptx: a "Slides" fieldset (`SlideOptions` in `SourceEditor.tsx`): notes, include hidden,
  look like slides, "Which slides" text, and a checklist of the deck's slides (from `meta.pptx`) that writes the
  range (all ticked → no range, so new slides come in too; hidden ones are disabled unless included).
- Selector in point mode selected: the preview shows its input with the marker; a click (the bridge reports `caret`
  offsets) opens "Point here": At the cursor, Before / After this <block> (sets the Selector's `point`). Object
  selected: "Where it goes" (its Point's document with the marker; clicks move the point when it comes straight from
  a point-mode Selector) or "Result". The Selector's inspector has "Point output" (place) for the other modes;
  `PointSummary` / `PLACES` live in `ObjectEditor.tsx`. The Extractor's inspector reuses `SelectorFields` without
  point (and `ManualSelections` for "Selected by hand"). An Extractor selected by hand has two preview views (`views`
  on `PreviewSource`): "Pick" (its input with the kept parts highlighted; selected text → "Add to <extractor>",
  `addAnchor`) and "Kept" (its output). `chooseMediaFile` adds an image or video file. Project files save every `fileId` found
  anywhere in a node's settings.
- Selected text in the preview → "Create selector from selection" (a new manual Selector connected to the
  shown document, `createManualSelector`) or "Add to <selector>" (`addAnchor`). Selecting a whole block gives
  an element anchor, anything else a text anchor. Highlighting never changes the text, so offsets stay valid.
- Snippet library UI: `src/ui/library` (no list in the left sidebar: a Snippet node's dropdown offers the library's
  snippets and "Edit in library" opens one; clicking a node, even the selected one, leaves the library editor;
  `LibraryEditor` in the inspector when `openSnippetId` is set: edits a draft, "Save as version N+1",
  "Used by" with update buttons, a "Try it" preview). Store actions: `saveSnippet`, `createSnippet`,
  `duplicateSnippet`, `deleteSnippet`, `useLibrarySnippet`, `updateNodeSnippet`, `detachSnippet`
  (gives the copy its own id so its CSS is not merged with the library version's), `saveNodeSnippetToLibrary`,
  `addSnippetNode`. Nodes show "Update available: vN" when the library has a newer version.
- Code fields use CodeMirror through `CodeField` (`fields.tsx`): loaded with `import()` (≈570 kB) and preloaded
  when the app is idle; a text area stands in until then. In e2e, wait for `.cm-content[aria-label=…]` before
  typing, and use `keyboard.insertText`.
- Persistence (`src/store/project.ts`): project file = `{ format: 'node-cms-project', version: 1, graph, files,
  library }`; binary files as base64; only files a node uses are saved. `parseProject` drops broken parts
  (unknown node types, bad connections, unreadable files or snippets) with warnings and refuses newer versions.
  The store autosaves to localStorage (`STORAGE_KEY`, 600 ms after changes to graph, files or library) and opens
  it on start; `exportProject` / `importProject` for project files. Tests pass `storage: null`.
- Undo/redo: zundo `temporal` on the store, tracking only `graph`, `files` and `library`. Edits to the same
  node's settings within `undoGrouping` (1 s) are one step (`groupKey` set by `updateConfig`); actions that
  change several things use `batch()` so they are one step; deletes go through `removeElements` (React Flow's
  `onDelete`) for the same reason. Keyboard: Ctrl/Cmd+Z, Ctrl+Y / Shift+Cmd+Z, ignored inside fields.
- `src/samples.ts`: sample content for the app's examples and for `scripts/make-fixtures.ts`.
- e2e helpers in `tests/e2e/canvas.spec.ts`: `connect(page, from, port, to, port)` drags between handles;
  call `fitView` first (it waits for the view to stop moving). The Playwright viewport is 1920×1080 (at 1440 the
  canvas between the three sidebars is too narrow for reliable drags between handles).
  `tests/e2e/preview.spec.ts` has `selectInPreview` / `selectElementInPreview` / `previewText`. After an
  action that changes highlights, wait for the new highlights before selecting again (the page reloads).
- The canvas fits the view only after loading an example, never while nodes are added (it would move them
  under the pointer).

## Commands
- `npm run dev`: dev server
- `npm test`: unit tests (must pass before every commit)
- `npm run e2e`: Playwright tests (builds, serves on :4173, headless Chromium)
- `npm run build`: type check + build
- `npm run fixtures`: regenerate the test .html, .docx, .pptx (pptxgenjs, `SAMPLE_DECK`) and .json files

## Definition of done for any task
Tests added, `npm test && npm run build` green, and a screenshot of the UI if it changed
(e2e tests write screenshots to `test-results/`).

## Roadmap
M0 scaffold · M1 document engine · M1b JSON import · M2 selectors and anchors · M3 snippet application ·
M4 graph engine · M5 canvas UI · M6 preview and visual selection · M7 snippet library · M8 persistence and export.
All planned milestones are done; since then: resizable / separate-window preview, Insert node, PowerPoint P1–P5
(text · tables, pictures, groups · source options and slide preview · Slide selector · slide-deck Output; the
PowerPoint work stops there: P6, shape positions, embedded media and theme colours / fonts, is not planned),
Connector that turns any input into any output, Extractor, Point output and Object node (replacing Insert),
Combinator, simple custom snippets with node-only CSS / JS. Ideas for later: merge node, subgraphs, evaluation in a Web Worker,
dark mode, rich-text JSON formats (ProseMirror, Portable Text).

## Deployment
`.github/workflows/pages.yml` runs unit tests, builds with `VITE_BASE=/<repo-name>/`, and deploys `dist/`
to GitHub Pages on every push to `main`. Local builds keep base `/`.
